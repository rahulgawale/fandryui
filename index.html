Why Fandry UI

Build Salesforce apps that look like your product, not the platform.

A modern, composable UI library for Salesforce LWC. Get design freedom, extensibility and control over your UI without adding another frontend framework.

Token-driven from the core

Set --fd-* tokens on :root to theme the whole site, or on one section to theme just that. They reach inside every component's shadow root.

Theme this section Default Editorial Midnight 
.checkout {
  /* --fd-primary: inherited */
  /* --fd-bg: inherited */
  /* --fd-radius-md: inherited */
  /* --fd-font-heading: inherited */
  /* nothing set: the site theme */
}

Gift wrap

Slots, not another prop

There is no loading flag: the spinner is markup you put in the slot, and you can put anything else there too. --fd-* tokens style the spinner and ::part() restyles any element inside.

<fandry-button>
  <fandry-spinner></fandry-spinner>
  Saving
</fandry-button>

fandry-button::part(base) {
  border-radius: 999px;
}

Features

What you get

Native shadow DOM, even on Salesforce

Plain Lightning Web Components in real, standards-based shadow DOM, on LWR and in your org, not the synthetic polyfill base components grew up on.

Lightweight & composable

Small, dependency-light primitives you compose with slots, not a dozen config props.

Your product, not the platform

Give your app or site its own type, colors and spacing instead of the standard Salesforce look.

Faster development

Sensible defaults and Claude Code-friendly source make every screen faster to build.

Design tokens, not magic numbers

Every color, spacing, and radius comes from one token scale you can retheme in a single place.

Accessible by default

WCAG AA-tuned color tokens, keyboard-first controls, and correct ARIA out of the box.

Components you control

Restyle with parts, replace content with slots, extend a state class, or copy the source. Nothing here is a black box.

Brandable

Reskin an entire site by changing tokens, not by rewriting components.

Boring, on purpose

No hidden state, no magic — every primitive does exactly one predictable thing.

Built for the real world

Real focus management, correct tab order, and Safari quirks handled, so you don’t have to.

Layout

Layout is just CSS

No Container or Grid components to learn. Two plain classes from global.css wrap ordinary primitives, and the grid finds its own columns as the space changes.

orders.html 
<div class="fandry-container">
  <fandry-heading>Orders</fandry-heading>
  <div class="fandry-grid">
    <fandry-card>…</fandry-card>
    <fandry-card>…</fandry-card>
  </div>
</div>

/* global.css */
.fandry-grid {
  display: grid;
  grid-template-columns:
    repeat(auto-fit, minmax(min(280px, 100%), 1fr));
  gap: var(--fd-space-6);
}
